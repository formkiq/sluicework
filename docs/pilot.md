# Pilot acceptance

Use two Apple Silicon Macs, a private GitHub repository, a prepared test-failure report and customer-controlled provider accounts. Record the macOS builds, Sluicework release, relevant run IDs, schedule occurrence times and the GitHub workflow URL. Keep account keys and private report contents out of the pilot record.

| Exercise | Procedure and expected result |
| --- | --- |
| Single Mac | Create a loopback cluster using the installer. Run an approved `/usr/bin/uname -m` script, reboot, confirm both launchd services have resumed and open the same run ID. |
| Second Mac | Enable cluster HTTPS and enrol the second worker using the verified CA and a one-use token. Confirm that reusing the token is rejected. Label only that machine `pilot-second`, then run a template requiring the label. Confirm its attempt shows that machine. Drain it, queue another run, and confirm the run is claimed only after clearing drain. |
| Claim and lease recovery | Give both online workers matching labels and one slot. Queue a single approved `/bin/sleep 120` job and check exactly one attempt is running. Disconnect its worker from the orchestrator through lease expiry. Inspect the interrupted attempt and unknown outcome. Reconnect and retry manually. Confirm both attempts remain in history. |
| Logs and cancellation | Run a trusted, administrator-owned script that prints a line, sleeps and prints another. Open live logs, reload the console while it runs and inspect the retained output. Cancel another run while connected and wait for confirmation. Repeat with a disconnected worker and verify interruption on lease expiry. |
| Recurring workflow | Use the example below to summarise the explicitly selected report. Schedule it in an IANA timezone. Record the next local execution, wait through it and check the single occurrence and run. Restart around the next occurrence and check that the wall-clock slot has at most one run. Stop across a later occurrence and check the missed record. |
| Inference across Macs | Host Ollama on the second Mac or register a Herd router. Provide an HTTPS endpoint trusted by the orchestrator for this LAN hop. Test from the orchestrator and run the AI job on a worker with the selected input. Stop the local endpoint and run again. The run should fail with the selected local connection and provider error. Restore the runtime and retest. |
| Cloud connections | For each of OpenAI, Anthropic and Gemini, add a customer key and allowed model, test, and run an explicitly cloud-enabled template on non-sensitive pilot text. Rotate the key, revoke the old key at the vendor and repeat. Check that an operator can view the run, model and usage while privileged connection edits require an administrator. |
| CI | Install the official self-hosted runner and register its scope, label and launchd target. Dispatch the pilot workflow to its custom label. Match the runner name in GitHub to the Sluicework machine and inspect local status before and after stopping the runner service. |
| Restore | Take an application backup after a completed run and scheduled occurrence. Restore on the replacement Mac, re-enter cloud keys, re-enrol each worker, verify a remote heartbeat and compare those IDs, logs and schedule timing with the originals. |

The example includes a small failure report and a local-only summary template. The worker holding the selected input can call a model hosted on another Mac through the orchestrator. Configure the local inference service's listener to be reachable only from the trusted orchestrator network. Model installation and replication are managed by the inference runtime.
